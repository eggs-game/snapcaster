# UI audit — 2026-10-11

This release focuses on settings and the surrounding game/account interface.
Card-recognition accuracy and latency results remain those of the preceding
`milo-photo-27` release. The diagnostic BUILD marker is `milo-ui-28`.

## Repaired behavior

- Invalid Commander choices and failed history writes show a dismissible error
  while keeping the table usable. Enter in the Commander form no longer
  activates its camera button.
- Restart clears pending ready checks, dice, stickers, damage and elimination
  state in both the interface and real transport. Reconnecting peers receive
  the opening turn instead of the previous active player.
- Space preserves focused switches, buttons, inputs, scrolling panels and
  dialogs. It passes the turn only from the table background.
- The elimination action occupies a row above the grid, leaving all player
  menus reachable after seat shuffling. Dropping a sticker no longer opens
  card lookup beneath it.
- Mobile navigation becomes a horizontal rail with a scrollable settings panel.
  Collapsing the panel gives that space back to the table.
- Hidden Chat retains unread state and scrolls to new messages when reopened.
  IME composition does not submit unfinished text. Whispers resolve full player
  names and overlapping prefixes without leaking into public chat.
- Deck text view includes selectable Commander and partner rows and displays
  quantities. Unknown mana values sort after known values. A late artwork
  response cannot replace another selected card's choices.
- Settings saves display confirmation. Account menus dismiss on outside click
  and Escape. Sign-out failures remain visible even if Supabase already cleared
  the local session. Successful account hydration clears stale load errors.
- Invitation and friend-removal failures stay recoverable, with busy states
  preventing duplicate notification actions.
- Account/deck text and counter stickers have readable contrast. Decorative
  deck artwork and tooltips no longer widen mobile pages; modal close controls
  remain in their intended corner.
- The landing-page illustration loads separately so the initial JavaScript
  remains below its existing 80 KiB gzip budget.

## Verification

The four-player tour covers 21 feature groups, including all general switches,
three appearance choices, three layouts, 12 tile colors, four quality choices,
ready acceptance/veto/timeout, public/private chat, sound categories and sender
cooldown, Coin/D3–D20, poison and Commander damage, sticker placement/movement/
removal/expiry, invitation copy/cancel, rename/flip, elimination/undo,
start/end/restart, removed-player isolation and reconnects. A visitor session
checks permitted chat/capture access and the absence of player/host controls.

Account checks cover 10 functional scenarios: settings persistence/export,
profile views/history/stats, deck import/edit/remove/hand tools, artwork races,
read-only decks, notifications, invitation errors and friend removal. The
layout audit covers eight routes in both themes at 1375×998 and 390×844:
32 views with zero axe violations, horizontal overflow or uncaught errors.
Screenshots were visually reviewed as well as checked automatically.

The compiled game tour also runs five WCAG scans across desktop/mobile game and
settings views. Browser fixtures block external mutations, and the drivers fail
on attempted production writes or uncaught page errors.

Reproduce using the commands in [testing.md](testing.md) and
[ui-simulation.md](ui-simulation.md). Release reports and screenshots are local,
ignored artifacts under `.cache/ui-simulation-release/`,
`.cache/ui-audit-release/account-pages/` and `.cache/ui-audit-pages/`.
Fast policy checks, the production build, the actual sidebar browser test,
the OAuth callback/sign-out failure test and representative compiled-page
accessibility checks also passed.

## Scope of the fixture

Three opponents, signaling, account data and persistence are simulated. The
React interface, HTML video playback, canvas MediaStream tracks and JPEG capture
are real. The fixture does not establish physical device quality, audible
output, WebRTC/TURN connectivity, live Discord behavior or durable production
database writes. Those require separate integration tests. The local practice
transport refuses public hostnames, and production builds remove its fixture.
