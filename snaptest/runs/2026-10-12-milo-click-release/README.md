# BUILD 35 recognition release evidence

This archive preserves the complete native control, final candidate and rejected
first candidate reports, including every row, capture hash, confidence value,
stage diagnostic and source/catalog fingerprint. These are warmed desktop
measurements of the actual compiled Game pointer handler, three native video
samples, production JPEG selection, local WebRTC transfer, recognition and a
decoded, fully opaque sidebar image followed by `requestAnimationFrame`.

The native timing gate and complete eight-suite recognition release matrix pass.
The precommit release checker recomputes the native policy from these raw reports,
binds all current source/catalog fingerprints and verifies the full matrix.
Production deployment is confirmed separately through the pushed commit status.

[Matrix reports and source proofs](matrix/README.md) preserve paired current-main
primary and supplied-photo results, six additional suites, exact driver source
and their checksum manifest. The primary retains all 189 earlier successes and
adds Anger (190/200); the supplied photographs retain all 198 prior successes.
Every confident answer is correct, and all eight suites have zero scan errors.
Those recognition-only timings exclude native capture, transfer and display.
[Moving-frame and cancellation controls](game-controls/README.md) preserve the
six exact moving pairs, clean latest-click controls and deliberate failing
negative controls. [Final native hint reports](game-controls/hints-final/README.md)
retain the full stale20, four valid repeat hints and Voja fallback. The stale
and unhinted arms both identify 19/20 correctly, preserving all earlier eighteen
winners and sixty exact JPEG/geometry pairs. All four verified repeats display
under one second, and the Voja fallback retains its printing/face. These selected
functional tests do not replace the complete native200 latency gate.

`native/pair.json` is regenerated by the tracked
`scripts/check_native_card_delivery_pair.mjs` using the archived
`native/control.json` and `native/candidate.json`. Both reports retain their
original bytes and SHA256. The validator accepts all 200 identical selected
JPEGs, geometry/order and catalog/model identities. Both arms record 20 opaque
camera scenes with equal raw RGBA after one and ten repaints. All 189 prior
winning printings, faces, pathways and confidence values are preserved; Anger
and Geier Reach Sanitarium are the two additional correct identities.

The predeclared policy in `policy.json` requires median ratio at most 1.05,
p90 ratio at most 0.85 and at least ten additional correct subsecond displays.
The final ratios are 0.9680 and 0.6063, with 17 additional subsecond displays.
The ordinary 0.9 median / five-subsecond-gain policy remains unchanged; this
run uses the explicit `--tail-improvement` policy, declared before the full
candidate outcome.

`native/rejected-pair.json` applies the same thresholds to
`native/rejected-candidate.json` and correctly fails: its subsecond gain is
zero. Its better p90 and two recovered identities were insufficient. The
original validation JSONs are retained as `native/original-*-pair.json`;
only the regenerated copies change their input paths to portable archive
references.

From the repository root, recompute the accepted gate:

```sh
node scripts/check_native_card_delivery_pair.mjs \
  snaptest/runs/2026-10-12-milo-click-release/native/control.json \
  snaptest/runs/2026-10-12-milo-click-release/native/candidate.json \
  --tail-improvement \
  --output=snaptest/runs/2026-10-12-milo-click-release/native/pair.json
```

Replacing `candidate.json` with `rejected-candidate.json` must exit with status
1. A saved `ok` field alone is not release evidence: the release checker reloads
both reports, checks their hashes and recomputes the policy.

Models and catalog are warm; the test clears recognition hints before each
fresh click. The static camera selects the first sample in all 200 cases.
Physical-camera noise, first-visit downloads, phone performance, remote
network/NAT/TURN and screen scanout are outside this measurement. Separate
moving-frame/newest-click controls are archived by their owners. This archive
keeps the common 20-scene manifest and pixel hashes, rather than duplicating
the source PNGs or JPEGs; it can recompute the report gates offline but does
not independently replay the browser benchmark without those fixtures.

## GPU worker regression

`gpu/browser-regression.json` preserves the actual compiled model-worker
regression under the recorded production CSP. Twenty public new-face JPEGs
(including four reverse faces) are replayed with identical bytes across a
forced-WASM arm, the default WebGPU arm and a blocked-GPU-runtime fallback.
All 40 complete ranked-row comparisons agree with WASM. The original
Cornelius detector remains usable before and after model queries.

Each arm performs 50 lookups, including 30 alternating repeats, with stable
observable WASM allocation sizes. The default arm actually adopts WebGPU;
destroying its two privately owned GPU devices triggers a labelled WASM
recovery (`gpuRecovered: true`) with unchanged ranked rows and functioning
Cornelius. Blocking GPU runtime initialization also selects WASM. Recorded
errors, CSP violations and blocked writes are empty.

The compiled worker SHA256 matches `source-bindings/candidate.json`. This is
retrieval, CSP, fallback and lifecycle coverage; it is not a full recognition
accuracy or click-latency benchmark. GPU memory allocations are not observable
through the recorded WASM memory instrumentation, and no GPU-memory bound is
claimed.

## Dimensions and source ownership evidence

`dimensions/report.json.gz` losslessly preserves all fields of the 18-case
dimensions-only experiment (11 prior native misses and seven safety controls).
`dimensions/summary.json` records identical complete printing/rival/source
proofs in all 18 pairs, six correct in each arm, no safety failures and a
134MB WASM heap. It tests retaining source dimensions before closing an
ImageBitmap; its recognition diagnostics are not end-to-end speed evidence.
The uncompressed report SHA256 is recorded in `archive-manifest.json`.

`source-bindings/control.json` binds the 70-file committed-main control
(`ae8d3d2ceb23180c6c512c360b86863d9c5bc461`).
`source-bindings/candidate.json` binds the final 71-file BUILD 35 source,
catalog, build inputs, compiled assets and production headers. Every final
native source digest agrees with that manifest and the separately frozen
private-v4 source-digest manifest. The rejected native source bindings are
retained independently: its Game, matcher and recognizer predate the final
candidate. All native arms use the same 113,269-entry catalog and Milo gallery.

`validation/metadata.json` records the exact regeneration commands, exit
statuses, validator SHA256, byte-preservation checks and source-binding
comparisons. Validation logs are retained, including the earlier fast-check
and build output. Historical absolute paths inside raw reports are preserved
as provenance; the regenerated pair uses relative archived input paths.
`archive-manifest.json` hashes these archive files and records original raw
report hashes for the gzip entry. No source code, fixture pixels or report
fields were modified to make the archived gates pass.
